# time-scale 設計ドキュメント

作成日: 2026-05-20

## 概要

1日の時間を「カテゴリ別持ち時間」として管理するモバイルアプリ。仕事・自己研鑽・趣味などを自分で定義し、Start/Stopタイマーで記録。カレンダーでその日の達成状況を確認できる。

## 技術スタック

| 要素 | 選定 |
|------|------|
| フレームワーク | React Native (Expo) |
| 状態管理 | Zustand |
| データ永続化 | expo-sqlite |
| 通知 | expo-notifications |
| プラットフォーム | iOS / Android |

将来的にGoogleログインおよびクラウド同期の追加を想定した設計とする。

## ナビゲーション

ボトムタブ3画面構成：

```
[ 今日 ] [ カレンダー ] [ 設定 ]
```

## データモデル

### categories

| カラム | 型 | 説明 |
|--------|----|------|
| id | INTEGER PK | |
| name | TEXT | カテゴリ名 |
| type | TEXT | `quota`（ノルマ）または `limit`（上限） |
| color | TEXT | カラーコード |
| weekday_budget_min | INTEGER | 平日の目標・上限（分） |
| weekend_budget_min | INTEGER | 休日の目標・上限（分） |
| sort_order | INTEGER | 表示順 |

### sessions

| カラム | 型 | 説明 |
|--------|----|------|
| id | INTEGER PK | |
| category_id | INTEGER FK | |
| date | TEXT | YYYY-MM-DD |
| started_at | INTEGER | Unixタイムスタンプ |
| ended_at | INTEGER | Unixタイムスタンプ（null = 計測中） |
| duration_sec | INTEGER | ended_at - started_at |

## タイプ定義

### ノルマ（quota）

やりたくないこと（仕事など）向け。時間が加算され、目標時間に達したらクリア。

- クリア条件: `合計duration_sec >= weekday/weekend_budget_min * 60`

### 上限（limit）

やりたいこと（趣味・自己研鑽など）向け。残り時間が減算され、5分以内の超過ならクリア。

- クリア条件: `合計duration_sec <= weekday/weekend_budget_min * 60 + 300`

## クリア判定

1日が「クリア」とみなされる条件：全カテゴリがクリア状態であること。

## 画面設計

### 今日の画面

- カテゴリカードのリスト
  - カテゴリ名・タイプ・進捗バー・残り時間 or 積算時間
  - 現在計測中のカテゴリはバナーで強調表示
- カテゴリをタップしてStart、もう一度タップまたはSTOPボタンで終了
- 設定時間に達したらpush通知

### カレンダー画面

- 月表示のグリッド
  - 緑: クリア、赤: 未クリア、薄色: 休日（土日・祝日）、青枠: 今日
  - 凡例なし
- 日付タップで詳細画面へ遷移
  - 各カテゴリの合計時間とセッション一覧（自動記録）を表示

### 設定画面

- カテゴリ一覧（名前・タイプ・平日/休日時間を一覧表示）
- カテゴリ追加・編集・削除
- 編集項目: 名前・タイプ（ノルマ/上限）・カラー・平日目標時間・休日目標時間
- 初期状態はカテゴリ空

## 通知

- カテゴリのStart時にスケジュール
- ノルマ: 目標時間到達時に通知
- 上限: 上限時間到達時に通知（5分猶予の開始を知らせる）
- ユーザーが任意で時間を設定してタイマー通知する機能も提供
